## 需要修正或补齐的地方

1. **历史记录中的旧命令不应继续沿用。** `left_hand.md` 把 `canon_in_d_major1` 当作左手权重的建议，已被 `left_hand_result.md` 的实测纠正。后续以 `cfg/two_demo.py` 配对应权重和曲谱为基线。文件名 `left_hand_motion.json` 实际包含双手。
2. **reset 的时序有一帧偏差。** `main.py` 在 step 后录制并给 dones 所在帧打 reset；实际 reset 在下一轮 `reset_done()` 执行。导入器却解释成该标记帧已经回到初态。应区分末帧 done 与下一段首帧，按片段导入，禁止跨片段插值。将来多环境录制也应只看被录制环境的 done。
3. **曲谱循环不等于环境重置。** `env.py` 的 `overtime_check()` 在 `goal_timer` 到期时调用 `reset_goal()`；录制器只看 dones，不能据“无 reset”证明未跨曲目循环。当前 `--max-steps` 仅固定时长，并非录制完整一遍曲目的停止条件。
4. **空间参考不足。** JSON 只保存 key_links，缺少吉他世界变换、掌部、真实指尖及 RH:pick，也没有源模型、曲谱、权重和时间原点元数据。静态节点可由 MJCF 固定层级推导，但必须应用正确的局部变换；优先显式导出关键参考，减少歧义。
5. **当前可视化不是角色骨架。** wrist→finger 的连线用于预览；不能直接作为解剖层级和绑定姿态。源网格还原需要处理 MJCF 的 mesh scale、geom 局部位姿、body 层级；刚体世界四元数也不能直接赋给目标 pose bone 的局部旋转。
6. **插值尚未明确约定。** 导入器未显式指定插值方式，也未处理四元数同半球连续性。现有片段没有符号翻转，但重采样、慢放、运动模糊前仍需明确策略并检查子帧表现。
7. **现有校验器覆盖有限。** 只检查三个固定名称的位移，不能支持所有单手文件；主要打印统计，未对完整数据模式及异常值做失败判定。因此旧记录中“全节点最大跳变 ≤ 0.04 m”不能成立。

## 建议实施顺序与验收

### 1. Blender 源场景还原（优先）

以现有 JSON 驱动仓库 STL/OBJ 源手网格；从 MJCF 还原吉他、琴弦/品位参考和网格偏移。未录制的固定子节点从最近已录制父节点推导，必要时补录。保存独立 .blend，保留原始节点动画供比对。

验收：可打开并播放完整片段；左右手、尺度、朝向正确；检查开头、帧 203 和帧 565–571 附近；核对指尖与指板、拨片与弦的相对位置。先保留原始动作，避免未经接触验证就平滑导致按弦漂移。

### 2. 录制协议和整曲边界

修复 reset 语义；记录片段/曲目循环标识、吉他及接触参考、曲谱进度、实际仿真时间和曲谱时间偏移；提供录完一遍停止能力。先用相同 checkpoint 与对应曲谱验证。整曲时长应考虑预备阶段、环境实际离散节拍与尾部动作，不能只用原曲 BPM 推算。

验收：完整演奏一遍，无中途拼接重置或重复开头；可对齐曲谱事件与动作；输出能追溯配置、权重、随机种子。

### 3. 一个确定角色的重定向与烘焙

明确目标角色的 Blender 版本、骨架/控制器名称、手型尺寸及静止姿态。建立源/目标绑定姿态校正与父子空间转换，以吉他为共同参考；先实现手腕和手指动作，再约束接触指尖/拨片，最后加入手臂 IK 和躯干配合。

验收：在目标骨架上生成可编辑 Action；烘焙后关闭源驱动仍可播放；按弦和拨弦关键时刻不明显悬空或穿透。FBX/BVH 等中间格式不是当前 Blender 内制作的必要前置步骤。
